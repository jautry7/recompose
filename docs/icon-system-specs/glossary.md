# Glossary

This glossary distinguishes authoring concepts, compiled catalog concepts, and project-specific terms used throughout these specifications.

| Term | Definition |
|---|---|
| **Appearance** | A visual mode for which an icon can supply different artwork or property values. Icon Composer presents **Default**, **Dark**, and **Mono**. The document schema serializes overrides as `dark` and `tinted`; macOS CoreUI resolves light/dark/tintable representations under multiple appearance identifiers. |
| **Appearance specialization** | An alternate value for one property under a particular appearance. In `icon.json`, a specializable property can be written either as one ordinary value or as a sibling key ending in `-specializations` containing an ordered array of values. |
| **Authored order** | The order in which Icon Composer writes groups and layers to `icon.json`. Observed documents list the frontmost item first. CoreUI's resolved arrays use the opposite order. |
| **Background record** | The first child returned in an observed compiled icon stack. It carries the icon's background fill rather than ordinary leaf artwork and is not counted as an authored group. Recognized names such as `system-light` and `system-dark` are semantic presets whose editable inverse is the matching string value; Dark specialization presence is a separate concern. |
| **Canonical form** | The representation that a current Icon Composer version writes or consistently interprets as the intended editable behavior. A noncanonical form can sometimes parse without preserving authoring semantics. |
| **Compiled order** | The order in which CoreUI returns resolved groups and leaves: back-to-front relative to Icon Composer's authoring arrays. |
| **Condition** | A selector used to resolve a compiled rendition, such as appearance, scale, device idiom, subtype, display gamut, locale, or layout direction. |
| **CSI** | CoreTheme Structured Image, a family of compiled rendition records used inside asset catalogs. Vector leaf data can be stored in a CSI/`ISTC` representation even though CoreUI exposes it as a Core Graphics SVG document at runtime. |
| **Default value** | The base value of a specializable property. It applies to the default appearance and participates in inheritance when a later appearance does not supply an override. |
| **Display gamut** | The color range requested during CoreUI lookup. The audit found both ordinary and Display P3/high-bit-depth raster alternatives. Selecting the default gamut alone can discard a higher-quality source. |
| **Fill** | A background or artwork treatment applied through Icon Composer rather than baked into source artwork. A fill can be absent (`"none"`), solid, linear-gradient, automatic-gradient, or a semantic system preset such as `"system-light"` or `"system-dark"`. |
| **Flattened companion** | A pre-rendered icon resource stored elsewhere in the same CAR alongside an icon stack. It is useful as an Apple-produced visual reference but is not the editable layer hierarchy and is not guaranteed to match Finder's final presentation. |
| **Group** | An ordered collection of leaf artwork that receives shared composition and material properties. Groups determine how elements stack and receive Liquid Glass treatment. |
| **Icon stack** | A layered logical icon asset. In the compiled runtime it is observed through an `IconImageStack`-like representation; in an authored document it is expressed through the root fill and group/layer hierarchy. |
| **`IconImageStack`** | The logical compiled asset type name seen in catalog metadata and runtime behavior. The exact private Objective-C class exposed at runtime has been observed as `CUINamedIconLayerStack` in the tested environment. |
| **Leaf or leaf slot** | One resolved artwork position inside a group. A corresponding slot can point to different files, properties, or media types in different appearances. |
| **Logical asset** | A user-meaningful named resource, such as `AppIcon`, that may resolve to many technical renditions. Logical assets are the correct unit for icon selection. |
| **Manifest** | In Recompose, an intermediate JSON representation produced by reading a compiled stack. It is not an Apple format. It preserves resolved CoreUI observations so a separate stage can construct an `.icon` document. |
| **Material annotation** | A property controlling system rendering rather than source pixels—for example glass participation, refraction, specular placement, blur, translucency, lighting mode, or shadow. |
| **Mono / tintable** | Two names seen at different layers of the system. Icon Composer's UI calls the third authored appearance **Mono**; the serialized specialization token is `tinted`; the compiled CoreUI appearance is observed as `ISAppearanceTintable`. |
| **Named lookup** | A CoreUI object found while enumerating catalog resources. Named-lookups are useful candidate sources, but enumeration alone does not reliably classify every icon stack. |
| **Presentation rendering** | Rendering performed by a system consumer such as Finder rather than the authoring preview. It is the required comparison boundary for claims about final system appearance and can expose semantic differences hidden by similar previews or flattened companions. |
| **Reconstruction pipeline** | The end-to-end process of reconstructing an editable `.icon` document from a compiled asset catalog. It includes extracting source artwork, normalizing variants, reversing order, translating values, and recording uncertainty. |
| **Rendition** | A compiled technical record selected for a particular set of conditions. Several renditions can implement one logical asset. Renditions are essential diagnostic evidence but are not normally what a user means by “the icon.” |
| **Resolved representation** | The concrete stack CoreUI returns after applying lookup conditions. An authored document stores specializations compactly; a resolved representation contains the effective values for one appearance and other requested conditions. |
| **Source artwork** | The SVG or raster graphic referenced by a leaf in an `.icon` document. After compilation, CoreUI can expose a vector as a Core Graphics SVG document and a raster as a `CGImage`. |
| **Specialization inheritance** | The observed rule by which omitted appearance variants of an ordinary specializable property inherit earlier effective values. In the tested document format, Dark inherits the base when absent, while Tinted/Mono inherits the effective Dark value when it has no distinct override. The root background is an exception: omitting Dark invokes Icon Composer's automatic system Dark background rather than preserving the base value. |
| **Structural fidelity** | The degree to which a reconstructed document preserves groups, leaf slots, source alternatives, and property values. |
| **Visual fidelity** | The degree to which a reconstructed document, after compilation, reproduces the original icon stack under equivalent system rendering conditions. A mismatch indicates a reconstruction defect or unresolved behavior rather than an expected difference between renderers. |
